# Acceptance Criteria

현재 요구사항, 관련 문서와 구현을 읽고 사용자가 직접 검수할 수 있는 acceptance 조건만 제시한다. 코드나 설정을 수정·삭제하지 않고 테스트 코드도 만들지 않는다. 사용자가 별도로 실행을 명시하지 않는 한 테스트 명령도 실행하지 않는다.

## 작성 방법

1. 검수 대상 기능과 사용자의 기대 결과를 한 문장으로 정의한다.
2. 관찰 가능한 동작을 기준으로 번호가 있는 acceptance 조건을 작성한다.
3. 각 조건에는 가능하면 사전 조건, 수행 동작, 기대 결과를 포함한다.
4. 관련 있는 경우에만 정상 흐름, 중복·재실행, 입력 오류, 외부 API 실패, 저장 결과, 주기 실행, 사용자에게 보이는 상태를 포함한다.
5. 구현 방식이나 특정 라이브러리를 acceptance 조건으로 고정하지 않는다. 요구사항이 불명확하면 가정과 확인이 필요한 항목을 분리한다.

## 보고 형식

- **검수 대상**: 무엇을 확인하는지
- **사전 조건**: 필요한 데이터나 실행 상태
- **Acceptance 조건**: 사용자가 판정할 수 있는 번호 목록
- **확인 필요**: 요구사항에서 결정되지 않은 사항

각 조건은 통과 또는 실패를 명확히 판정할 수 있어야 한다. 코드 변경, 리팩터링, 의존성 추가, 실제 데이터 삭제 같은 조치를 제안 없이 수행하지 않는다.
