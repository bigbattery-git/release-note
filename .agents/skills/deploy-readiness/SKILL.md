# Deploy Readiness

배포 준비 여부를 읽기 전용으로 진단한다. 이 질문은 코드 수정, 삭제, 자동 수정, 실제 배포를 허가하지 않는다.

## 점검 절차

1. `git status`와 관련 패키지의 manifest 및 설정을 읽어 점검 범위를 정한다.
2. 저장소에 이미 정의된 검증 명령 중 관련 있는 lint, typecheck, test, build를 확인한다.
3. 기존에 설치된 의존성만 사용해 안전한 검증 명령을 실행한다. `--fix` 옵션, formatter 쓰기 모드, 의존성 설치·업데이트, migration, 실제 배포, 외부 시스템 변경은 실행하지 않는다.
4. Build가 일반적인 ignored 산출물만 생성하는 경우에는 실행할 수 있다. tracked 파일 변경, 사전 정리 또는 외부 서비스 변경이 예상되면 실행하지 않고 그 이유를 보고한다.
5. 점검 전후의 `git status`와 `git diff --check`를 비교한다. 검증 과정에서 예상하지 못한 파일 변경이 생기면 되돌리거나 삭제하지 말고 즉시 사용자에게 알린다.

## 판정과 보고

다음 중 하나로 결론을 시작한다.

- **배포 가능**: 필요한 검증이 모두 성공했고 알려진 차단 요인이 없다.
- **배포 보류**: 실패한 검증이나 명확한 차단 요인이 있다.
- **판정 불가**: 필요한 명령, 의존성, 환경 또는 외부 서비스가 없어 충분히 확인하지 못했다.

실행한 명령과 결과, 실행하지 못한 점검과 이유, 남은 위험을 구분해 보고한다. 문제를 발견해도 수정하지 않으며 가능한 해결 방향만 설명한다.
