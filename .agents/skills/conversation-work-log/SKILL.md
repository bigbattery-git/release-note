# Conversation Work Log

현재 대화에서 실제로 수행한 작업을 `docs/rules/work_log.md`에 맞는 Work Log로 남긴다. 이 trigger는 Work Log 작성 요청이며 소스 코드나 설정을 추가로 변경할 권한은 아니다.

## 작업 절차

1. `docs/rules/work_log.md`를 처음부터 끝까지 읽고 최신 형식과 작성 원칙을 따른다.
2. 현재 대화의 사용자 요청, 수행한 파일 작업, 명령 결과를 검토한다. 생성·수정·삭제된 파일과 그 이유, 발생한 문제, 해결 과정, 직접 수행한 검증을 구분한다.
3. `git status`, `git diff`와 현재 파일을 읽어 대화 기록과 최종 상태가 일치하는지 확인한다. 대화 시작 전부터 존재했거나 이 대화에서 수행했다고 확인할 수 없는 변경은 현재 작업으로 단정하지 않는다.
4. `docs/work_logs/`의 기존 파일을 확인한다. 같은 작업의 기존 로그를 보완하는 경우 해당 문서를 수정하고, 별도 작업이면 기존 최대 번호 다음 번호로 새 `NNN_제목.md`를 만든다. 번호를 재사용하거나 기존 로그를 덮어쓰지 않는다.
5. Work Log 외의 소스 코드, 설정, 테스트 또는 다른 문서는 수정하거나 삭제하지 않는다.
6. 작성 후 파일명, 번호, 필수 내용, 실제 변경 및 검증 결과와의 일치 여부를 확인한다.

## 기록 경계

- 현재 대화에서 실제로 완료한 작업만 기록한다.
- 제안만 했거나 실행하지 않은 명령은 완료 또는 성공으로 쓰지 않는다.
- 실패한 접근이 최종 결과에 영향을 주었을 때만 증상, 원인, 해결, 재검증을 기록한다.
- 코드 변경과 문서 변경을 구분하고, 삭제가 없었다면 삭제가 있었다고 만들지 않는다.
- 민감한 값, 불필요한 전체 로그, 대화 원문을 복사하지 않는다.
- 근거가 부족한 내용은 추정하지 말고 미확인 사항으로 표시한다.

완료 보고에는 작성하거나 보완한 Work Log 경로와 기록한 작업 범위를 간단히 알린다.
